# dotfiles

Workstation configuration, kept in git so settings survive a re-install.
Symlinks are managed with [GNU stow](https://www.gnu.org/software/stow/); every
top-level directory except `scripts/` is a stow package whose contents mirror
the layout of `$HOME`.

## requirements

Install Homebrew, then `git` and `stow` — enough to fetch this repo and link it:

```shell
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)" && brew install git stow
```

```shell
git clone https://github.com/levivannoort/dotfiles ~/.dotfiles
```

## installation

```shell
cd ~/.dotfiles && make install
```

`make install` installs everything in the Brewfile and symlinks every package.
Run `make help` for the full list of targets:

| target | what it does |
| --- | --- |
| `make install` | `brew` + `stow` |
| `make brew` | install everything in the Brewfile |
| `make stow` | symlink all packages into `$HOME` |
| `make check` | dry-run stow and report conflicts, touching nothing |
| `make unstow` | remove every symlink |
| `make restow` | unstow then stow (picks up renames and deletions) |
| `make macos` | apply macOS system defaults |
| `make migrate-claude` | move Claude runtime state out of the repo |
| `make lint` | shell, yaml and vimrc checks |

Every path is derived from the Makefile's own location, so the repo works from
any clone path and any user account. Override the link target with
`make stow TARGET=/somewhere/else`.

## layout

| package | links to | notes |
| --- | --- | --- |
| `brew` | `~/.config/brew/Brewfile` | |
| `claude` | `~/.claude/` | config only — see below |
| `fzf` | `~/.fzf.zsh` | generated by fzf's installer |
| `ghostty` | `~/.config/ghostty/config` | launches tmux directly |
| `git` | `~/.gitconfig`, `~/.gitignore` | |
| `k9s` | `~/.config/k9s/` | |
| `kube` | `~/.kube/kuberc` | kubectl aliases and flag defaults; `k` itself stays in `.zshrc` |
| `tmux` | `~/.tmux.conf` | |
| `vim` | `~/.vimrc` | plugin-free, it is `$EDITOR` |
| `zsh` | `~/.zshrc`, `~/.local/bin/` | |

Not stow packages:

- `scripts/` — one-shot helpers run by hand or via `make`, never symlinked.
- `aws/template/config` — a reference `~/.aws/config` using
  [granted](https://granted.dev) for SSO. Copy and fill in per machine; it is a
  template on purpose, since account ids and role names are environment
  specific.

## claude

`~/.claude` holds both configuration *and* runtime state — conversation
transcripts, `history.jsonl`, caches, and `.claude.json` backups. Only the
configuration belongs in git.

Two mechanisms keep it that way, and both matter:

- **`--no-folding`**, applied to every package in the Makefile. Without it stow
  replaces a missing target directory with a single symlink, which would make
  `~/.claude` point into this repo and cause Claude Code to write all of its
  runtime state inside the working tree. `--no-folding` creates real
  directories containing per-file symlinks instead.
- **an allowlist in `.gitignore`**, so only `settings.json`, `CLAUDE.md`,
  `commands/` and `agents/` are trackable. A `pre-commit` hook
  (`scripts/check-no-claude-state.sh`) and a CI job enforce the same rule,
  because `git add -f` overrides `.gitignore` but not those.

If `~/.claude` is currently a symlink into this repo — the folded layout — run
`make migrate-claude` **with no Claude Code session active** to convert it.
The script refuses to run while a session is live and asks before moving
anything.

## development

```shell
make lint          # zsh -n, yamllint, vimrc load check
make check         # stow dry run
pre-commit install # run the hooks on every commit
```

CI runs the same linters, stows into a scratch directory to assert the symlink
layout, and fails if anything but Claude config is tracked under
`claude/.claude/`.
